# ДЗ6: Автодеплой Jobby через GitHub Actions

## Задача

Настроить автоматическое развёртывание бэкенд-приложения на удалённом сервере при обновлении кода в выбранной ветке собственного GitHub-репозитория. Для проекта Jobby используются микросервисы на Node.js, PostgreSQL, RabbitMQ, Docker Compose и Nginx.

## Ход работы

### Триггер и область применения

Файл `.github/workflows/jobby-deploy.yml` расположен в корне репозитория. Workflow срабатывает при push в ветку `jobby-deploy`, когда меняются исходники микросервисов, файлы развёртывания или сам workflow. Проверка `github.repository` ограничивает выполнение форком `offvoki/ITMO-ACS-Backend-2026-A`. Ветка для сдачи работ не запускает развёртывание автоматически.

### Этап сборки

На GitHub-hosted runner выполняется checkout, проверка конфигурации Docker Compose и последовательная сборка шести образов. Этап deploy запускается только после успешного этапа build.

### Этап развёртывания

Workflow создаёт архив каталогов `labs/lab23` и `labs/lab4` без зависимостей, результатов сборки и локальных секретов. Архив передаётся на сервер по SSH и распаковывается в `/opt/jobby/releases/{SHA}`. Скрипт `labs/lab4/deploy-release.sh` использует тот же Compose project `jobby`, что и ручное развёртывание ЛР4; поэтому сохраняются постоянные Docker-тома баз данных и RabbitMQ.

Секреты приложения остаются на сервере в `/opt/jobby/lab4/.env.deploy`. Если файла ещё нет, скрипт `prepare-env.sh` создаёт случайные значения паролей и ключей. Образы на сервере собираются по одному из-за малого объёма оперативной памяти. Затем Docker Compose обновляет контейнеры, а скрипт ожидает успешного ответа пяти маршрутов `/health/{service}` через Nginx и проверяет работу notification-service. Только после успешной проверки ссылка `/opt/jobby/current` переключается на новый релиз.

### Доступ к серверу

Адрес сервера, закрытый SSH-ключ и проверенный SSH host key хранятся как GitHub Actions secrets: `JOBBY_SSH_HOST`, `JOBBY_SSH_PRIVATE_KEY`, `JOBBY_SSH_KNOWN_HOSTS`. Они не включаются в исходный код или отчёт. Подготовка ключа, добавление секретов и первая отправка ветки `jobby-deploy` описаны в `homeworks/hw6/README.md`.

### Проверка результата

После настройки секретов и отправки ветки `jobby-deploy` в разделе GitHub Actions должен завершиться зелёным запуск `Jobby deploy`. В его журнале должны быть видны завершение сборки, сообщение `Deployment succeeded` и успешные HTTP-проверки. На сервере можно проверить `docker compose ps` и публичные маршруты `/health/user`, `/health/vacancy`, `/health/resume`, `/health/application`, `/health/dictionary`.

На момент подготовки отчёта workflow ещё не отправлен в GitHub и фактический запуск автодеплоя не подтверждён. Это будет проверено после настройки секретов и push ветки `jobby-deploy`.

## Вывод

Подготовлена конфигурация CI/CD, которая связывает обновление выбранной ветки форка со сборкой, передачей релиза и обновлением приложения на удалённом сервере. Успешность реального развёртывания должна быть подтверждена запуском GitHub Actions после отправки ветки и настройки доступа к серверу.
